# Command UX Follow-up

This checkpoint covers local source changes, not a published release.

## Corrected issues

- Generic button styling replaced the facility grid with centered flex content.
  Facility cards now retain their three-column artwork, copy and action layout.
- Fixed-size quantity presets inherited padding and word breaking; `10` could
  wrap into two lines. Numeric presets now have zero padding and no wrapping.
- The reports toolbar used `pw-activity-toolbar`, while the previous shared
  override targeted a different class. Its heading and count now have a real
  vertical layout, readable type and a mobile full-width refresh action.
- Market inline labels at 8-11px and tracked monospace fonts were normalized
  through TypeScript syntax-tree edits. Trading logic and values are unchanged.
- Quest requirements and listing instructions now have explicit spacing.
- Wallet address values no longer inherit uppercase text transformation.
- Queue percentages measured time since browser mounting, not total job time.
  Active jobs now show the chain finish-time countdown without false percentages.
- Transaction confirmation, recovery and technical-detail styling existed only
  in preview mode. `operation-feedback.css` styles the actual OperationModal.
  Successful feedback is nonblocking; pending/error dialog semantics remain.
- Quest loading starts before presenting claim controls on the first read.
- Fleet preflight now rejects the exact departure coordinates before signing,
  matching the existing program rule. Program code and economics are unchanged.
- Populated fleet assignments, available counts and destination/cargo labels now
  use the readable shared type scale and explicit gaps, rather than the legacy
  tiny monospace styles which were invisible in the empty-fleet review.
- Scene loading timeout now counts visible-page time only. Chrome pauses frames
  in hidden tabs; those pauses must not consume the renderer's timeout budget.
  Scene readiness remains mandatory, including recovery after a real timeout.
- The system-view account trigger now separates avatar and truncated address,
  with a fixed mobile width instead of clipping text past the viewport.

## Verification

- Opened all ten actual command screens locally at desktop and 390x844 mobile
  sizes. Dialogs stayed inside the viewport; checked controls had no horizontal
  overflow. Store/alliance/market content was inspected after loading separately
  from the initial loading-state traversal.
- Visually checked facility alignment, readable report toolbar, numeric presets,
  market resource-listing form and wallet layout. Wallet remains scrollable and
  Escape returns focus to its opener.
- The real OperationModal component was extracted with the TypeScript parser
  and rendered with React for success, pending and error component checks.
  These isolated HTML checks are not simulated gameplay transaction evidence.
- Local fleet form checks blocked own-coordinate targets, cargo beyond capacity
  and fractional ship quantities. No mission was sent by these checks.
- Production build succeeded after the restricted Windows sandbox initially
  denied access to a planet image. Existing large-bundle/deprecation warnings
  remain; this is not a performance audit.
- Final regression suite: 110 passed, zero failed; TypeScript passed.

## Boundaries

The localhost server does not expose the production serverless wallet/NFT APIs.
Local wallet setup/balance and UFO activation labels were not treated as live
account truth; actual gameplay ran on the production devnet address instead.
No NFT artwork or owned assets were invented for component testing.

Alliance-member/governance views, populated trading books, combat reports,
colony flows and funded purchase/withdrawal states still require appropriate
accounts and live test activity. Their complete UX is not certified by these
empty-state and component checks. Publication requires user approval.

Final cold reload found Chrome reporting `document.visibilityState === 'hidden'`
with an unrendered 300x150 canvas. The original loading watchdog expired even
though the browser was not supplying frames. The visibility-aware timeout has
a tested correction, but final real-frame verification needs Chrome brought
to the foreground. Do not mark the complete visual review passed or publish
on the strength of unit tests alone. The new system-account trigger still
needs that final mobile visual recheck too.
